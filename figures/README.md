# `figures/` — generated report figures

Every image here is regenerated from the per-patient CSVs in [`../results/`](../results/) by a `make_figure*.py` script in [`../src/`](../src/). None was drawn or edited by hand, so a figure and the corresponding table in the report cannot drift apart.

| File | Generated by | Shows |
|---|---|---|
| `fig_architecture.png` | `make_figure_architecture.py` | Pipeline schematic: contrastive text-volume alignment at training time, sliding-window heatmap extraction at inference. Method section. |
| `fig1_dice_vs_volume.png` | `make_figures.py` | Per-patient Dice against true lesion volume, with the chance-level control overlaid. The core RQ1 result. |
| `fig2_rq1_vs_rq2.png` | `make_figures.py` | RQ1 vs. RQ2 mean Dice by region and size bin. |
| `fig3_example_overlays.png` | `make_overlay_figure.py` | Qualitative heatmap overlays on one large and one small example lesion, showing the blocky sliding-window structure directly. |
| `fig4_scale_comparison.png` | `make_figure4_scale_comparison.py` | RQ1 vs. RQ3b vs. RQ4 grouped bars. |
| `fig5_window_curve.png` | `make_figure5_window_curve.py` | Mean Dice against query window size (32³→6³), one line per region. |
| `fig_leaderboard.png` | `make_figure_leaderboard.py` | Every method's mean Dice, one panel per region, grouped by size bin. |
| `fig_roadmap.png` | `make_figure_roadmap.py` | Decision tree of every ablation attempted, colour-coded by whether the outcome helped, hurt, or partly fixed the prior problem. |
| `fig_significance_heatmap.png` | `make_figure_significance_heatmap.py` | Every paired significance test in one panel, recomputing the Wilcoxon tests and BH correction from the CSVs at draw time. |

## Cached intermediates

| File | Purpose |
|---|---|
| `large_example_BraTS20_Training_225.npz` | Cached heatmap + volume for the large-lesion overlay panel. |
| `small_example_BraTS20_Training_298.npz` | Cached heatmap + volume for the small-lesion overlay panel. |

Both are written by `generate_example_heatmaps.py`, which needs a GPU; caching them lets `make_overlay_figure.py` redraw the figure on the login node without recomputing the sliding-window pass.

## Caveat when reading the comparison figures

`fig_leaderboard.png`, `fig4_scale_comparison.png`, `fig5_window_curve.png` and `fig_significance_heatmap.png` all plot **Otsu-thresholded** Dice, the project's original protocol. Section 7.11 of the report shows the smaller-window advantage these figures display does not survive a better-calibrated binarizer. They are accurate depictions of the Otsu-thresholded comparison and should be read with that section alongside them.
